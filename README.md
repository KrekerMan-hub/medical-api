# Medical API 1.0

Учебный REST API для работы с записями пациентов. Позволяет добавлять пациентов, получать список и отдельную запись, изменять диагноз и удалять записи.

Проект создан для практики Python, FastAPI и SQL. В примерах используются вымышленные данные. Авторизация и разграничение доступа пока не реализованы; проект предназначен для локального обучения.

## Возможности

- Создание пациента с автоматическим назначением ID.
- Получение списка пациентов порциями с помощью limit и offset или одного пациента по ID.
- Изменение диагноза.
- Удаление пациента.
- Проверка входных данных: возраст от 0 до 120 лет, непустые имя и диагноз.
- Удаление пробелов по краям имени и диагноза; строки из одних пробелов отклоняются.
- Ответ 404, если пациент не найден.
- Хранение данных в SQLite: сохранённые записи остаются после перезапуска приложения.

## Технологии

- Python 3.13
- FastAPI — маршруты и обработка HTTP-запросов.
- Pydantic — описание и проверка данных.
- SQLite — база данных.
- Uvicorn — сервер для запуска приложения.

## Запуск на Windows

Установите Python 3.13. Откройте PowerShell в папке проекта, где находятся `main.py`, `database.py` и `schemas.py`.

### 1. Создайте виртуальное окружение

```powershell
py -3.13 -m venv .venv
```

Если команда `py` недоступна, укажите полный путь к установленному Python:

```powershell
& "C:\путь\к\python.exe" -m venv .venv
```

Замените пример пути на свой. Виртуальное окружение хранит зависимости проекта отдельно. Следующие команды обращаются к нему напрямую, поэтому активировать его не требуется.

### 2. Установите зависимости

```powershell
.\.venv\Scripts\python.exe -m pip install fastapi "pydantic>=2,<3" uvicorn
```

SQLite входит в стандартную библиотеку Python, отдельно устанавливать его не нужно.

### 3. Запустите сервер

```powershell
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
```

`main:app` означает объект `app` из файла `main.py`. Параметр `--reload` перезапускает сервер при изменении кода и используется при разработке.

### 4. Откройте документацию

[Swagger UI — http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

Выберите маршрут, нажмите **Try it out**, заполните данные и нажмите **Execute**. Для остановки сервера нажмите **Ctrl+C** в терминале.

## Маршруты API

| Метод | Адрес | Назначение | Успешный ответ |
| --- | --- | --- | --- |
| GET | `/` | Проверка работы API | 200 |
| GET | `/about` | Информация о проекте | 200 |
| POST | `/patients` | Добавить пациента | 201 |
| GET | `/patients` | Получить список пациентов | 200 |
| GET | `/patients/{patient_id}` | Получить пациента по ID | 200 |
| PATCH | `/patients/{patient_id}/diagnosis` | Изменить диагноз | 200 |
| DELETE | `/patients/{patient_id}` | Удалить пациента | 200 |

`{patient_id}` — ID нужного пациента. Для чтения, обновления и удаления отсутствующей записи API возвращает 404. При неверных входных данных возвращается 422.

## Пример использования

### Добавить пациента

Выполните `POST /patients` с телом запроса:

```json
{
  "name": "Анна",
  "age": 28,
  "diagnosis": "ОРВИ"
}
```

Пример ответа с кодом 201:

```json
{
  "name": "Анна",
  "age": 28,
  "diagnosis": "ОРВИ",
  "id": 1
}
```

ID назначает база данных. В дальнейших запросах используйте ID из своего ответа: он может отличаться от 1.

### Изменить диагноз

Для пациента с ID 1 выполните `PATCH /patients/1/diagnosis`:

```json
{
  "diagnosis": "Бронхит"
}
```

Успешный ответ:

```json
{
  "message": "Диагноз обновлён"
}
```

Выполните `GET /patients/1`, чтобы получить запись с обновлённым диагнозом.

## Проверка работы вручную

1. Создайте отдельную тестовую запись и запомните её ID.
2. Найдите её в списке и получите по ID.
3. Измените диагноз и проверьте результат через GET.
4. Перезапустите сервер и убедитесь, что запись сохранилась.
5. Попробуйте передать имя или диагноз из одних пробелов — ожидается 422.
6. Удалите тестовую запись. Повторное удаление и получение по её ID должны вернуть 404.
